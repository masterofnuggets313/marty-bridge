# marty-bridge

Руки агента в браузере и в Telegram. Локальный мост, расширение Chrome и набор команд.

Агент открывает страницы, читает их, кликает, заполняет поля, снимает скриншоты и пишет сообщения в Telegram Desktop. Браузер при этом обычный: без порта отладки, без флагов запуска, без отдельного профиля.

```
mb open https://hh.ru/vacancies
mb probe
mb do '[{"op":"click","text":"Откликнуться"},{"op":"probe"}]'
mb tg send "Избранное" "готово"
```

---

## Зачем это

Агент, который не видит браузер, работает слепо: он пишет код, но не проверяет, что получилось. Порт отладки (`--remote-debugging-port=9222`) решает половину задачи и создает три проблемы: нужен отдельный запуск с флагом, нужен отдельный каталог профиля, и после обычного перезапуска браузера все ломается.

Расширение с разрешением `debugger` получает тот же протокол CDP изнутри браузера. Значит:

- работает после любого запуска, флаги не нужны;
- видит вкладки, куки и сессии, где вы уже залогинены;
- не требует отключать защиту профиля.

## Что умеет

Браузер:

- список вкладок, переключение, открытие, закрытие;
- выполнение JS в любой вкладке, 15-40 мс на шаг;
- полный CDP: настоящие клики мышью, ввод, клавиши, скриншоты;
- чтение страницы одной командой: адрес, заголовки, поля, кнопки, сообщения об ошибках;
- сценарии из десятков шагов за один вызов, с проверкой условия после каждого шага.

Telegram Desktop:

- открыть чат по названию, отправить текст, отправить файл;
- прочитать переписку скриншотом;
- защита от отправки не в тот чат по заголовку окна.

Чего не умеет и не будет:

- обходить капчу и защиту от ботов;
- работать без вашего браузера и ваших сессий;
- читать Telegram через UI Automation (интерфейс рисуется сам, текста наружу нет);
- работать на macOS и Linux в части Telegram (там нужен Windows).

## Быстрый старт

Нужен Python 3.10 или новее и браузер на Chromium (Chrome, Яндекс, Edge).

**1. Пакет.**

```bash
git clone https://github.com/masterofnuggets313/marty-bridge.git
cd marty-bridge
python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux и macOS
source .venv/bin/activate

pip install -e .
# нужен Telegram: добавьте канал
pip install -e ".[telegram]"
```

**2. Расширение, один раз.**

1. Откройте страницу расширений: `chrome://extensions` или `browser://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку `extension` из этого репозитория.
5. Убедитесь, что Marty Bridge в списке и включен.

Путь к папке печатает `mb status`, если расширение еще не подключено.

**3. Мост.**

```bash
mb up
mb status
```

`mb up` поднимает мост и вкладку-сторож. `mb status` показывает, на связи ли расширение, сколько вкладок и виден ли Telegram.

## Как это устроено

```
агент -> mb -> 127.0.0.1:8765 -> вкладка-сторож -> воркер расширения -> chrome.debugger -> вкладка
```

Тонкость, из-за которой все сделано именно так: служебный воркер расширения Chrome усыпляет примерно через 30 секунд простоя, и висящий запрос его не удерживает. Поэтому опрос моста живет не в воркере, а в сторожевой вкладке `http://127.0.0.1:8765/`:

- `keepalive.js` внедряется в эту страницу и постоянно держит длинный опрос;
- воркер просыпается на сообщение от вкладки, выполняет команду и отвечает;
- вкладка закреплена, иначе браузер ее выгрузит, а у выгруженной вкладки нет страницы, значит нет и опроса.

Страница моста сама себя диагностирует. Она каждые 2 секунды спрашивает у моста, когда тот последний раз получал опрос от расширения, и честно пишет состояние: «на связи», «ждем расширение», «расширение молчит N сек», «мост не отвечает». Если связи нет дольше 8 секунд, страница перезагружается сама, до 8 раз с растущей паузой, потом сдается и пишет, что делать.

Решение о перезагрузке принимается по полю `age` из `/health`, а не по метке скрипта. Первый заход с меткой ушел в цикл перезагрузок и рвал опрос на полуслове.

## Команды

| Команда | Что делает |
|---|---|
| `mb status` | мост, расширение, вкладки, Telegram |
| `mb up` / `mb down` | поднять / остановить мост |
| `mb ping` | проверка связи с расширением |
| `mb diag` | диагностика расширения и вкладки-сторож |
| `mb tabs` | список вкладок, звездочкой рабочая |
| `mb use 123456` | выбрать рабочую вкладку |
| `mb open https://...` | открыть вкладку |
| `mb close 123456` | закрыть вкладку |
| `mb probe` | карта страницы одним вызовом |
| `mb text "h1"` | текст элемента |
| `mb js "document.title"` | выполнить JS |
| `mb jsf query.js` | длинный JS из файла |
| `mb find "Отправить"` | где элемент и его координаты |
| `mb shot page.png` | скриншот |
| `mb do '[шаги]'` | сценарий строкой |
| `mb run steps.json` | сценарий из файла |
| `mb tg send "Чат" "текст"` | написать в Telegram |
| `mb tg look "Чат" out.png` | открыть чат и снять скриншот |
| `mb cdp attached` | кто держит отладчик на вкладках |
| `mb autostart` / `mb autostart-off` | автозапуск при входе в систему |

## Сценарии

`probe` это главный ускоритель разведки: один вызов вместо десяти `find` и `text`. Дальше сценарий собирается уже по карте страницы.

```json
[
  {"op": "open", "url": "https://example.com/form"},
  {"op": "fill", "label": "Имя", "value": "Герман"},
  {"op": "check", "label": "Согласен с условиями"},
  {"op": "click", "text": "Отправить", "expect": {"text": "Спасибо"}},
  {"op": "probe"}
]
```

Шаги: `open, use, close, goto, reload, back, wait, click, check, fill, select, type, press, text, attr, extract, js, probe, scroll, shot, sleep`.

Полезные поля шага:

- `expect` проверка после действия, строка или `{"text": "..."}`, `{"gone": "..."}`, `{"sel": "...", "visible": true}`, `{"url": "..."}`, `{"value": "...", "field": "..."}`;
- `index` какой по счету элемент брать, если текст совпал у нескольких;
- `settle` пауза перед кликом в миллисекундах, по умолчанию 150;
- `timeout` для `open` и `wait`;
- `as` метка шага в отчете.

Если проверка после `click` не прошла, шаг повторяется один раз: часто мешает анимация или поздний рендер.

Вывод: по строке JSON на шаг плюс итоговая сводка. На ошибке сценарий останавливается и показывает, на каком шаге.

## Telegram

Веб-версия часто недоступна без VPN, приложение на машине работает всегда. Читать переписку через UI Automation нельзя: интерфейс рисуется сам, наружу отдается только контейнер без текста. Поэтому:

- писать штатно: навигация поиском, текст через буфер обмена, Enter на отправку;
- читать скриншотом, текст с картинки снимает зрение;
- перед отправкой сверяется заголовок окна, если открылся не тот чат, текст не уходит.

Ловушки, которые уже обойдены:

- `Ctrl+F` в Telegram ищет внутри открытого чата, а не по чатам. Поэтому поиск идет кликом по полю «Поиск» в левой панели;
- буфер обмена после вставки возвращается на прежнее содержимое;
- файл кладется в буфер через PowerShell `Set-Clipboard -LiteralPath`, текстовый буфер файл не передает.

## Автозапуск

```bash
mb autostart
```

Пишет ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение запускает наставника через `pythonw.exe`, окна консоли нет. Наставник держит мост живым и открывает вкладку-сторож, если она пропала после перезапуска браузера.

Логи: `bridge.log` и `supervisor.log` в каталоге данных, по умолчанию `~/.marty-bridge`.

## Безопасность и границы

- **Мост слушает только 127.0.0.1.** Наружу порт не открывается.
- **Кто угодно на этой машине может отправить команду.** Мост не требует пароля, это осознанный выбор: он и нужен для того, чтобы локальный агент им пользовался. Не запускайте мост на машине с чужими учетными записями.
- **Расширение имеет доступ к вашим сессиям.** Оно кликает в залогиненном браузере. Не ставьте его в профиль, где открыты чужие аккаунты, и не давайте агенту задачи, которые вы не сделали бы сами.
- **Telegram.** Отправка проверяет заголовок окна, но не заменяет вашу голову. Все, что уходит людям, должно быть прочитано вами.
- **Капча.** Это сигнал остановиться, а не задача для обхода. В проекте обхода нет.

Подробнее в [SECURITY.md](SECURITY.md).

## Связка с другими проектами

Мост ничего не знает про конкретные задачи, поэтому им пользуются снаружи. Пример: [hh-autopilot](https://github.com/masterofnuggets313/hh-autopilot) ищет вакансии через API hh и для второго канала отклика зовет `mb`.

## Ограничения

- браузер на Chromium: расширение использует `chrome.debugger`, в Firefox этого нет;
- Telegram только Windows: нужен UI Automation и буфер обмена Windows;
- порт по умолчанию 8765 прописан в манифесте расширения, смена порта требует правки `extension/manifest.json` и `keepalive.js`;
- мост один на машину: второй экземпляр увидит занятый порт и не поднимется.
